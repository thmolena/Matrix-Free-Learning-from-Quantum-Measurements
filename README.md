# Applied Mathematics for Quantum Computing

**Structure-preserving and physics-informed numerical methods for quantum dynamics.**

[Project report and interactive demo](https://thmolena.github.io/QuantumPINNs-Physics-Informed-Neural-Networks-for-Quantum-Relevant-Physical-Modeling/)

## Highlights

- **Physicality by construction — with proof.** A Cholesky density network makes non-physical quantum states *architecturally unrepresentable* (Hermitian, positive semidefinite, unit-trace at every step). This is proven, not penalized.
- **A learned open-system model that generalizes.** Trained on a single initial state, the recovered Lindblad generator predicts *held-out* initial states of a dissipative two-qubit gate at ≈0.98 mean fidelity.
- **Near-exact system identification.** On a driven, damped qubit the framework recovers the Hamiltonian and dissipation parameters to 0.1–9% and reaches ≈1.00 trajectory fidelity, beating an unconstrained baseline on every parameter.
- **Matrix-free, accelerator-aware compiler.** A symbolic open-system specification lowers to structured kernels that avoid the `d²×d²` Liouvillian and run 5–13× faster than dense evaluation — designed for batched GPU execution.
- **Six mathematical guarantees + full reproducibility.** Exact physicality, CPTP preservation, universal approximation, an a-posteriori error certificate, local identifiability, and a compiler-complexity theorem — with every figure and number regenerated by committed scripts and a passing test suite.

## Summary

This repository brings an applied-mathematics perspective to quantum computing: differential-equation solvers and learning methods that respect the operator structure of quantum systems, are backed by provable guarantees, and are designed to scale on accelerators. It has two pillars.

**1. Reproducible validation on quantum model problems.** Physics-Informed Neural Networks (PINNs) are benchmarked on canonical quantum systems, with every quantitative claim drawn directly from committed CSV artifacts. The principal result is a **148x reduction in ground-state relative L2 error** on the harmonic oscillator when a physics-constrained loss replaces an unconstrained neural baseline on the same task and architecture. The same pattern extends through the shared benchmark suite: specialist Hamiltonian constraints outperform the non-specialist protocol by **76x** on the harmonic-oscillator ground state, a deeper model improves on the shallow baseline by **5.3x**, and under **20% input noise** error improves by **2.4%** rather than degrading — evidence that physics-based regularization strengthens both accuracy and robustness.

**2. Open quantum systems research.** A structure-preserving residual-learning framework infers physically admissible Markovian generators from sparse, noisy observations — the mathematics of quantum device characterization, noise modeling, and control. It enforces a positive, unit-trace density matrix by construction, keeps the learned generator completely positive and trace-preserving, lowers a symbolic open-system specification to dense or matrix-free GPU-scalable kernels, and is supported by six mathematical guarantees with reproducible qubit and qutrit experiments. See [Open Quantum Systems Research](#open-quantum-systems-research) below.

## Open Quantum Systems Research

Real quantum processors are never described by an ideal Hamiltonian alone — relaxation, dephasing, leakage, crosstalk, and control-induced dissipation make the density matrix the object that must stay physical throughout. The `submission/` directory contains a research manuscript and code that treat learning these dynamics as an applied-mathematics problem: inferring a physically admissible Markovian (GKSL/Lindblad) generator from sparse, noisy observations.

| Contribution | What it guarantees |
|---|---|
| Cholesky density network | The state `A·Aᵀ / Tr(A·Aᵀ)` is Hermitian, positive semidefinite, and unit-trace **by construction**, at every iteration and evaluation point — invalid states are unrepresentable rather than penalized. |
| CPTP generator parameterization | Softplus-positive rates and positive semidefinite Kossakowski matrices keep the learned generator a completely positive, trace-preserving semigroup. |
| Matrix-free open-system compiler | A symbolic specification lowers to either a dense Liouvillian or a structured residual kernel that stores `H` and the `m` jump operators instead of a `d²×d²` superoperator, targeting batched GPU kernels and larger Hilbert spaces. |
| Six mathematical guarantees | Exact physicality, universal trajectory approximation, CPTP-semigroup preservation, a trace-norm residual-to-error certificate, local identifiability from the sensitivity Gramian, and a dense-versus-structured compiler complexity theorem. |

Five reproducible CPU experiments (`submission/code/experiments/`) test the framework: a **qubit inverse problem** (near-exact parameter recovery, ≈1.00 fidelity, beats the unconstrained baseline), a **sparse-measurement ablation** (one-to-two orders of magnitude lower trajectory error than the baseline, robust to 10% observation), a **two-qubit dissipative gate** (the learned generator generalizes to held-out initial states at ≈0.98 fidelity), a **compiler scaling ablation** (5–13× faster than dense, exact agreement), and a **qutrit reconstruction** study (Fourier time-features lift reconstruction fidelity from 0.88 to 0.95). The work is deliberately reproducible and modest in scale — not hardware data or a state-of-the-art claim — and the limitations (rate identification in the fast-oscillatory regime, no hardware validation) are stated plainly. This direction maps directly to quantum device characterization, noise modeling, and control.

## Comparative Findings

All quantitative statements below are drawn from committed CSV artifacts in `outputs/`. Comparison models are limited to configurations explicitly evaluated in the project records.

| Measured result | Project model | Comparison model | Why the gain matters |
|---|---|---|---|
| Ground-state harmonic-oscillator relative L2 error | **0.001569** | 0.2323 from the unconstrained tanh baseline | **148x lower error** means substantially more faithful eigenstate recovery for the confinement settings used in this project as proxies for molecular vibrations and trapped-ion motional modes. |
| Specialist Hamiltonian formulation on QHO `n = 0` | **0.001569** | 0.1196 from the shared non-specialist protocol | **76x lower error** shows that eigenvalue consistency, normalization, and symmetry constraints improve performance beyond what shared architecture alone achieves. |
| Shared benchmark architecture depth, 5 layers x 64 units | **0.2658** | 1.4193 from the 2-layer x 64-unit baseline | **5.3x lower error** indicates that the stronger shared configuration transfers more effectively across the study's confinement, tunneling, and transport problem families. |
| Noise robustness in the shared benchmark | **0.2503** at 20% input noise | 0.2565 on the clean-input reference run | **2.4% lower error under corruption** shows that the model remains reliable when inputs are imperfect, which is directly relevant to measurement-like transport data. |
| Collocation efficiency for the shared QHO study | **0.24794** with 100 collocation points | 0.24773 with 2000 collocation points | **Within 0.1% of the denser setting** means essentially the same reported accuracy can be reached with 20x fewer collocation points. |

## Quantum Relevance

The benchmark families map to the building blocks of real quantum platforms — confinement for trapped-ion and neutral-atom registers, tunneling for charge and flux qubits, and time-dependent transport for characterization experiments. The statements below interpret only the positive comparative evidence reported in the benchmark outputs.

### Molecular vibrations and trapped-ion motional modes

The harmonic-confinement benchmark is used in the study as a representative structure for molecular vibrations and trapped-ion motional dynamics. The 148x improvement over the unconstrained baseline means the learned eigenstate follows the target mode shape much more closely in the canonical setting used to anchor those applications.

### Tunneling systems such as ammonia inversion and coupled quantum dots

The shared benchmark is designed to transfer beyond quadratic confinement into tunneling structure. The 76x specialist gain and 5.3x depth-driven gain show that the better-performing configurations preserve useful accuracy when the problem requires symmetry-sensitive behavior across multiple basins.

### Electron imaging, neutron interferometry, and cold-atom transport

The transport-facing result highlighted by the study is robustness. Error improves rather than deteriorates when 20% input noise is injected, indicating that the physics-constrained formulation is better matched to measurement-like conditions where inputs are not perfectly clean.

## Reproducing the Artifacts

```bash
conda activate qaoa
pip install -r requirements.txt

jupyter nbconvert --to notebook --execute --inplace notebooks/pinn_harmonic_oscillator.ipynb
jupyter nbconvert --to notebook --execute --inplace notebooks/pinn_schrodinger.ipynb
jupyter nbconvert --to notebook --execute --inplace notebooks/quantum_pinn_combined.ipynb

jupyter nbconvert --to html notebooks/pinn_harmonic_oscillator.ipynb --output pinn_harmonic_oscillator.html
jupyter nbconvert --to html notebooks/pinn_schrodinger.ipynb --output pinn_schrodinger.html
jupyter nbconvert --to html notebooks/quantum_pinn_combined.ipynb --output quantum_pinn_combined.html

python -m src.train --problem harmonic_oscillator --epochs 5000 --collocation 2000 --model-path model.pt
python -m src.server --model-path model.pt --problem harmonic_oscillator
python -m http.server 8000
```

### Web interfaces

- The root `index.html` is the self-contained GitHub Pages entry point. It contains the full report and embedded notebook viewer and needs no running server.
- `website/index.html` is a local developer interface that calls the Flask API in `src/server.py` (expected at `http://localhost:5000`). From the repository root, run `python -m http.server 8000` and open `http://localhost:8000/website/`.
